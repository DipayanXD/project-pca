PROJECT DETAILS REPORT

1. Project Title

Campus Resolve — Student Complaint Management System

2. Problem Statement

Students frequently encounter facility, infrastructure, and equipment-related problems across campus — such as malfunctioning classroom fans, non-functional lab computers, water cooler breakdowns, and damaged lab equipment — but lack a structured, transparent mechanism to report them and track resolution. Traditional verbal or manual complaint processes often result in untracked tickets, lack of accountability, and zero visibility for students regarding repair timelines. Campus Resolve provides a centralized, role-based platform enabling students to report grievances with location details and monitor progress through an audit timeline, while campus administrators efficiently prioritize, investigate, update, and resolve complaints with verifiable accountability.

3. User Roles

The system defines two distinct roles, fulfilling the BCAC591 project specification:

  • Student (Complainant) — Registers with student credentials and department; signs in to access a personal workspace dashboard; submits categorized complaints specifying location, description, and optional file attachments; monitors the real-time status and historical timeline of their own complaints; and manages their account profile.
  • Administrator (Campus Operations / Authority) — Authenticates via a separate administrative portal; oversees campus-wide operations through an analytics dashboard (reviewing pending queues, active tickets, resolution rates, and 7-day activity charts); reviews all submitted grievances across departments; updates ticket statuses (Pending → In Progress / Under Review → Resolved / Rejected) with official remarks; and monitors registered student accounts.

5. Database Tables (Draft / Active Schema)

The database campus_resolve is configured using MySQL with foreign key constraints and utf8mb4 encoding:

Table: users
Column Type / Notes
idINT, Primary Key, Auto Increment
user_codeVARCHAR(20), Unique (e.g. 'ST-2016', 'AD-001')
nameVARCHAR(100), Not Null
emailVARCHAR(120), Unique, Not Null
passwordVARCHAR(255), Not Null — stored using password_hash() (Bcrypt)
roleENUM('student', 'admin'), Not Null, Default 'student'
departmentVARCHAR(100), Default NULL (enforces 12 institutional academic departments)
statusENUM('active', 'inactive'), Not Null, Default 'active'
created_atDATETIME, Default CURRENT_TIMESTAMP

idINT, Primary Key, Auto Increment

categoryENUM('Infrastructure', 'IT', 'Facilities', 'Laboratory', 'Other'), Not Null
locationVARCHAR(150), Not Null (e.g. 'Block B · Room 204')
descriptionTEXT, Not Null
attachmentVARCHAR(255), Nullable (relative path to uploaded evidence file)
statusENUM('Pending', 'In Progress', 'Resolved', 'Rejected'), Default 'Pending'
created_atDATETIME, Default CURRENT_TIMESTAMP
updated_atDATETIME, Default CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
